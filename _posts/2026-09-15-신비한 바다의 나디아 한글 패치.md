MCP로 초벌 작업을 하면서 확실히 느낀 게 있다.

고유번호 작성, 대사 스크립트, 타이틀 로고 재배치 같은 단순 작업은 하위 모델에서 스킬과 하네스로 꽉 잡아서 진행하였다.

하나의 매우 작은 agent.md는 공유하지만 개별적인 내용은 그 에이전트 모델만 담당하여 다른 존재를 확인하지 못한다. 나눠진 에이전트 모델들은 연관성이 절대 없는 독립적인 기능만 구현하도록 분업해 놓았기에 별 문제가 없었다.

근데 확실히 AI가 발전할수록 상위 모델에서의 스킬과 하네스도 점점 무의미해지는 것 같다. 오히려 이러한 제한이 기존 모델의 성능, 토큰, 컨텍스트만 잡아먹는 병목이 되는 것 같기도 하다.

상위 모델에서는 입력 시스템 구현, 렌더러 코드 변경, 최적화를 담당했다.

그래도 생각보다 처음에 나온 코드는 문제가 굉장히 심했다. 여전히 아직까지는 과설계, 과검증이 심하다고 느낀다.

몇 가지 이야기하자면, 먼저 사람이 이해하기 힘들게 작성하는 것이다. 한 번만 사용해야 할 값도 따로 라벨링을 거쳐 복잡하게 만든다.

일반적으로 코드 패치를 할 때는 피연산자일 경우 그 값만 ".org"에 워드 단위로 작성하는 게 아니라, 명령어와 함께 한 라인에 적고 간단하게 주석 처리하면 될 것인데, 지침을 줘도 수정이 필요한 값만 워드 단위로 기재해 놓거나 명령어 자체를 헥스 코드를 쓰는 것이였다.   

코드 케이브에서는 많은 라벨링을 거쳐서 선형적으로 적어야 할 코드가 조건 분기도 아닌데 JMP를 써서 쓸데없이 코드 계층이 깊어지는 것까지 확인했다.

무엇보다 가장 황당했던 순간은 간단하게 데이터로 있어야 할 것이 런타임에서 그 구조를 만드는 코드를 보았다.

물론 한글화란 게 돌아가면 그만이지만, 쓸데없는 코드로 오버헤드가 커져 성능에 영향을 주는 것들은 확실히 고쳐야 한다고 생각한다. 특히 고전 게임기 같은 경우는 말이다.

만약 이런 부분을 무시하고 그간 작업했다면, 파일 시스템이나 CD-ROM을 사용하는 게임기에서도 로딩 속도를 고려하지 않고

부트 후 초기화 단계에서 빌트인에서 작성한 코드를 메모리에 미리 올리는 대신, 파일 I/O 커맨드나 최적화되지 않은 고전 BIOS의 함수를 남발했을 것이다.

내가 결과적으로 원하는 MCP는 단순히 "해줘"만으로는 아직까진 수많은 문제가 있으며, 프로그래머가 쉽게 확인하고 관리가 가능한 MCP를 만드는 것이 목적이다.

따라서 조금 더 생각하고 업데이트할 필요가 있을 것 같다.

---

현재까지 확실히 가능한 것들을 말해보자면

그렇게 까다롭지 않는 매퍼는 변환이 가능하다.

그다음은 고유번호와 대사를 뽑고, 이 롬에서 기존 CHR-ROM 방식을 쓸지 CHR-RAM 방식을 쓸지 판단하는 것이다.

예를 들어 대사가 적고 경우의 수가 얼마 없다면, CHR-ROM 방식을 채택해 필요한 CHR 타일 세트를 미리 만든다.

반대로 대사가 많으면 CHR-ROM 타일 세트를 일일이 구성하기 어렵다. 따라서 CHR-RAM으로 변환하고, 필요한 글자를 동적으로 갱신하면서 고정적으로 쓰는 글자는 인덱스를 재사용한다.

일단 롬을 CHR-RAM을 사용하는 구조로 변경하고, 해당 매퍼에서 지원하는 최대 용량까지 확장한다. 기존 CHR-ROM 데이터는 PRG-ROM으로 옮기고, 부트 후 초기화 단계에서 CHR-RAM에 복사한다. 이후 렌더러 코드를 수정해 한글 폰트를 출력한다. 

---

아직 제대로 해결하지 못하는 것들을 난이도 순으로 나열해 보면

1. CPU 사이클을 계산해 VBlank 안에 몇 타일을 전송해야 최적의 결과가 나오는지 판단하지 못한다. NMI에서 처리하는 다른 작업까지 고려해야 하는데, 전송량을 지나치게 작게 잡으면서 화면을 표시할 때까지 불필요하게 많은 프레임을 기다리게 된다.

2. 고정적으로 재사용해야 할 글자와 그때그때 갱신해야 할 글자를 구분하지 못한다. 이를 해결하지 못하면 원본 롬보다 표시 속도가 크게 느려진다. 특히 기존 8×8에서 8×16 폰트로 바뀌면 글자당 전송량이 두 배가 되어 문제가 더 심해진다. 숫자처럼 표시할 값이 바뀌더라도 글리프 자체는 같은 경우, 타일을 다시 전송하지 않고 배치할 인덱스만 바꾸면 된다. 이런 부분은 고정 인덱싱을 사용하거나 CHR-RAM에 미리 올려둔 타일을 재사용해야 한다.

3. 가장 심각한 문제는 현재 매핑된 CHR 뱅크에서 더 이상 사용할 공간이 부족해서 스캔라인 IRQ로 화면 구간에 따라 뱅크를 잠깐 전환해서 출력해야 할 때다. 해당 구간에 필요한 폰트는 알아도 같은 구간에 함께 표시되는 배경이나 창 테두리 등의 그래픽이 어떤 타일을 사용하는지 파악하지 못한다. 폰트만 생각하고 뱅크를 전환하면 그 구간의 다른 그래픽이 깨지는 것이다.

이 부분이 지금 가장 큰 난관이며, 어떻게 해결해야 할지 잘 모르겠다. 무엇보다 시간과 토큰 낭비가 너무 심하다.

아무튼 이런 고생을 하면서 더러운 코드지만 관리가 어느 정도 가능한 패치를 만들었다. 확실히 NES의 6502 코드는 상위 기종에서 컴파일러가 생성한 코드와 달리 사람이 직접 작성한 경우가 많아서, 오히려 작성자의 의도와 코드 흐름이 더 직관적으로 드러나는 것 같다.

추가로 게임 중 스탯을 바로 확인할 수 있도록 루아 스크립트를 IPC 브릿지로 파이썬에서 아군과 적군의 스탯 값을 실시간으로 확인하는 것도 재미 삼아 만들어봤다. 이외에 인터넷에 떠도는 게임지니 코드나 디버그, 숨겨진 요소들도 조금 확인해봤는데, 기존 원본 롬에서도 제대로 적용되지 않는 경우가 있는 것 같아 귀찮아서 더 분석하지 않았다.

매번 구조가 다른 롬을 하나 하나 분석하기보다, 자신만의 표준화된 방식을 정립하고 이를 활용하는 방향으로 개발한다면 더 나은 결과로 이어질 거라 생각한다.

## 구현된 방식

1. nes2.0 변경 및 CHR-ROM → CHR-RAM 변환 후 ROM 레이아웃

    ```
    $00~$0F : 원본 PRG 실행 코드/데이터        		
    $10~$1F : 원본 CHR-ROM 그래픽 데이터       		
    $20~$21 : 코드 케이브	
    $22~$26 : 문자열 포인터,문자열 데이터
    $27~$30 : 12x12 한글 폰트 kr_font.bin
    $31     : 초성, 중성, 종성 테이블 hangul_keys.bin
    $32     : 조합값에 대응하는 완성형 한글 고유번호 테이블 hangul_codes.bin
    $33~3D  : 빈 영역
    $3E~$3F : 고정 뱅크  
    ```

2. 8x8 -> 8x16 폰트로 변경
3. 초성 중성 종성 입력 시스템 구현
4. 좌표 수정, 메뉴창 크기 수정 
5. 동적 갱신 + 고정 타일 인덱싱 조합으로 부분 최적화
6. 조사 구현

## 간단한 게임 공략

1. 50 면을 클리어하면 55까지 맵이 개방되며 모두 클리어해야 엔딩이 나옴
2. CPU 턴에서 생각을 많이 하는 턴이 있는데 원본 롬도 똑같으며 프리징이 아니므로 배속 기능 활용할 것
3. 맵에서 사용하는 기술들은 죽여도 경험치를 얻지 못함
4. 롱 기술을 사용해서 맵에서 체력을 깍아놓고 마무리는 이동력이 좋은 캐릭터 활용하여 막타를 챙겨 성장하는 방식을 추천

```lua
local function buildLine(unit)
    local lv    = read8(unit.base + 0x03)
    local exp   = read16(unit.base + 0x06)
    local hp    = read16(unit.base + 0x08)
    local mp    = read16(unit.base + 0x0A)
    local maxHp = read16(unit.base + 0x0C)
    local maxMp = read16(unit.base + 0x0E)

    return string.format(
        "%s|%d|%d|%d|%d|%d|%d",

        lv,
        exp,
        hp,
        maxHp,
        mp,
        maxMp

    frame = frame + 1

    -- 약 10Hz
    if frame % 6 ~= 0 then
        return
    end

    local lines = {}

    table.insert(lines, "[ALLY]")

    for _, c in ipairs(allies) do
        table.insert(lines, buildLine(c))
    end

    table.insert(lines, "[ENEMY]")

    for _, e in ipairs(enemies) do
        table.insert(lines, buildLine(e))
    end

    local packet = table.concat(lines, "\n")

    udp:send(packet)
end

emu.addEventCallback(
```

```python
import socket
import sys
import os
import unicodedata

HOST = "127.0.0.1"
PORT = 5005

if os.name == "nt":
    os.system("")

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind((HOST, PORT))


def display_width(text):
    width = 0

    for ch in text:
        if unicodedata.east_asian_width(ch) in ("W", "F"):
            width += 2
        else:
            width += 1

    return width


def pad_right(text, width):
    current = display_width(text)
    return text + (" " * max(0, width - current))


def pad_left(text, width):
    current = display_width(text)
    return (" " * max(0, width - current)) + text


def parse_packet(text):
    allies = []
    enemies = []

    target = None

    for raw in text.splitlines():
        line = raw.strip()

        if not line:
            continue

        if line == "[ALLY]":
            target = allies
            continue

        if line == "[ENEMY]":
            target = enemies
            continue

        if target is None:
            continue

        parts = line.split("|")

        if len(parts) != 7:
            continue

        name, lv, exp, hp, max_hp, mp, max_mp = parts

        try:
            target.append({
                "name": name,
                "lv": int(lv),
                "exp": int(exp),
                "hp": int(hp),
                "max_hp": int(max_hp),
                "mp": int(mp),
                "max_mp": int(max_mp),
            })

        except ValueError:
            continue

    return allies, enemies


NAME_W = 16
LV_W = 6
EXP_W = 10
HP_W = 16
MP_W = 16


def build_units(units):
    lines = []

    for u in units:
        lv = f"Lv{u['lv']}"
        exp = f"EXP {u['exp']}"
        hp = f"{u['hp']}/{u['max_hp']}"
        mp = f"{u['mp']}/{u['max_mp']}"

        line = (
            pad_right(u["name"], NAME_W)
            + pad_left(lv, LV_W)
            + pad_left(exp, EXP_W)
            + pad_left(hp, HP_W)
            + pad_left(mp, MP_W)
        )

        lines.append(line)

    return lines


sys.stdout.write("\x1b[2J")
sys.stdout.write("\x1b[?25l")
sys.stdout.flush()

last_screen = ""

try:
    while True:
        data, _ = sock.recvfrom(65535)

        try:
            text = data.decode("utf-8")
        except UnicodeDecodeError:
            continue

        allies, enemies = parse_packet(text)

        lines = []

        lines.extend(build_units(allies))

        lines.append("")

        lines.extend(build_units(enemies))

        screen = "\n".join(lines)

        if screen != last_screen:
            sys.stdout.write("\x1b[H")
            sys.stdout.write(screen)
            sys.stdout.write("\x1b[J")
            sys.stdout.flush()

            last_screen = screen

except KeyboardInterrupt:
    pass

finally:
    sys.stdout.write("\x1b[?25h")
    sys.stdout.write("\n")
    sys.stdout.flush()
    sock.close()
```
